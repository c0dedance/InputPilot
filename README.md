# InputPilot

一个从零实现的 macOS 菜单栏输入法切换工具。Swift + SwiftUI + AppKit + 系统 TIS 输入源接口；没有第三方依赖，没有后台服务或固定轮询。

这是按已确认行为重新设计的实现，不复制 AutoSwitchInput Pro 的反编译代码、图标、界面资源或配置，也不读取它的偏好设置。运行本工具不需要 REA 或 Reverse-skill，它们属于此前的分析阶段。

## 现在怎样打开试玩

环境要求：macOS 13 或更新版本，Xcode 和 Swift 6 工具链。本机已用 Apple Silicon、macOS 15.7.2、Swift 6.2.4 编译验证，无须另外安装依赖。

1. **在屏幕顶部原软件的菜单中**：先暂停或退出 AutoSwitchInput Pro，以及其他自动切换输入法的工具。InputPilot 不会替你退出它们。
2. **打开 macOS“终端”窗口**：可按 Command + 空格，输入“终端”，按回车。在终端粘贴以下一整行，再按回车：

       bash "/Users/luoxiaohong/Downloads/tempProject/REA/InputPilot/scripts/run.sh"

3. **观察终端**：应看到 Build complete!、valid on disk，以及“构建和本地签名校验通过”。首次构建需要等待。随后脚本请求系统打开应用。
4. **在屏幕顶部菜单栏**：找到键盘图标及当前输入源名称，点击后选“显示主界面”。没有 Dock 图标是正常的。若设置窗口已经出现，直接使用即可。
5. **在 InputPilot 设置窗口**：首次应显示“还没有应用规则”。点击左下角“＋”或“添加应用…”，在系统文件选择器中选中一款 .app，点击“选择应用”。直接在新增表格行中选择输入法，选择后自动保存。再为另一款应用设置不同的输入法。
6. **切换到这两款应用的窗口**：检查系统输入法是否随应用规则变化；找一个普通文本编辑框试打几个字。更改或保存规则本身不会立即切换，离开设置窗口进入目标应用时才生效。

生成的应用包位置：

    /Users/luoxiaohong/Downloads/tempProject/REA/InputPilot/dist/InputPilot.app

脚本不需要 sudo，不会安装到“应用程序”，不会启用登录启动。若 InputPilot 已在运行，脚本会停止并提示先从其菜单中退出，不会强制结束进程。后续也可以在 Finder 中双击生成的应用包；要重新编译时仍使用上面的命令。

不要用 swift run 来启动：本工具需要完整的 .app 身份，尤其是菜单栏和登录项功能。运行脚本负责组装这个应用包。

## 建议按顺序试玩

| 在哪里操作 | 操作 | 预期结果 |
|---|---|---|
| 两款已设置规则的应用 | 来回切换窗口 | 进入时选择对应输入法 |
| 某款目标应用内 | 手动用系统菜单或系统快捷键切换输入法 | 保留你的选择，不立即抢回；菜单栏显示实际输入源 |
| 另一应用 → 原目标应用 | 离开后再次进入 | 再次应用该目标应用的规则 |
| 没有规则的应用 | 切换进去 | InputPilot 不更改输入法；系统或其他工具仍可能自行切换 |
| 设置窗口 → 自动切换 | 关闭开关后切换应用 | 开关旁显示“已关闭”，菜单栏显示“暂停”，不应用规则 |
| 设置窗口 → 自动切换 | 打开开关 | 显示“已启用”；检查当前前台应用，如果前台是设置窗口，则等进入目标应用时生效 |
| 设置窗口 → 输入法列 | 直接打开某行的下拉框，选择另一个输入法 | 自动保存，无需点编辑或另点保存；下次进入该应用时生效 |
| 设置窗口 → 启用规则列 | 取消某行右侧勾选 | 仅停用这一条规则，仍保留它指定的输入法 |
| 设置窗口 → 程序名称列 | 点击选中一行，再点左下角“−” | 删除该规则并保存；没选中行时“−”不可用 |
| 设置窗口 → ＋ | 再次选择已有规则的同一应用 | 选中已有行，不创建重复项；在该行直接修改输入法 |
| 系统设置 → 键盘 → 文本输入 | 移除某条规则指定的输入法，然后进入目标应用 | 明确提示目标不可用，不挑另一个输入法代替 |
| InputPilot 菜单 | 退出后再次运行脚本 | 规则和暂停状态恢复 |
| 设置窗口 | 关闭窗口 | 菜单栏继续运行；只有菜单中的“退出”会退出程序 |

快速切换应用时，代码使用处理当下的前台应用，不使用通知里可能过时的应用对象。自动测试覆盖这一调用边界；真实快速切换、macOS 自身行为以及第三方输入法兼容性仍需要这轮人工试玩。

## 按参考截图调整的操作界面

核心区域采用原生表格：应用图标、程序名称、行内输入法下拉框、启用规则复选框。左下角“＋／−”管理规则，右下角提示“未设置规则：保持当前输入法”，旁边的圆形箭头刷新可用输入源。

菜单栏下拉只保留“显示主界面”、分隔线和“退出”，快捷键分别为 Command+, 和 Command+Q；菜单栏本身仍显示实际输入源和暂停状态。设置顶部是“自动切换”原生开关与“已启用／已关闭”文字，右侧显示当前输入源；底部“登录时启动”使用同样的“名称 → 开关 → 状态”排列。已删除截图红框中的行为说明，切换行为没有改变。关闭自动切换即暂停，恢复开启会继续应用已有规则；配置保存失败时保留原状态并显示错误。

添加应用后直接进入表格，输入法列显示“请选择输入法”，不再弹出单独表单。选择输入法后立即保存并启用；未选择的行仅暂存在当前视图，不写入配置，重启后不保留，可用减号移除。重复选择应用只选中已有行。操作栏不显示规则数量；“刷新输入法”重新读取系统可用输入源，系统输入源变化时也会自动更新。下拉框标明失效的输入法；名称过长会截断，鼠标停留可查看完整名称及 ID。图标从系统读取，不复制原软件资源。若找不到已安装的应用，显示问号图标和说明，不删除规则。

参考截图中的“强制英文符号”和“默认输入法”没有加入本版：右侧复选框明确表示“启用规则”，无规则的应用仍保持当前输入法。全局暂停与单条规则停用互相独立。配置格式没有变，已有规则可直接沿用。

## 登录启动：单独测试，默认不登记

在 **InputPilot 设置窗口底部** 打开“登录时启动”开关。界面查询 SMAppService.mainApp.status，不另存一个本地成功开关：

- “已关闭”：尚未登记，开关关闭。
- “已启用”：系统报告已启用。
- “待批准 · 尚未启用”：已登记但尚未获准运行。开关保持打开以便你随时关闭、取消登记；点击“打开系统登录项设置…”，在 macOS 系统设置中决定是否允许，回到 InputPilot 时重新查询状态。
- “系统未找到登录项”或红色错误说明：登记没有成功，请保留错误文字反馈。

更新期间开关暂时不可操作，旁边显示“正在更新…”。失败时显示具体错误，开关回到系统实际的登记状态；例如取消失败后仍可能保持打开，不假装已经关闭。

当前构建使用本地临时签名（ad-hoc），不是 Developer ID 公证发行版；系统是否接受登录项要实际验证。登录项失败不会阻止基础的手动启动和规则切换。开启后不要随意移动或删除 dist/InputPilot.app；要移动或删除前，先在本工具中关闭登录启动。首次启动不会自动注册；若你此前已注册过同一应用，界面会如实显示系统现状。

## 行为和数据保存

- 一款应用一条规则，以 bundle ID 区分应用；输入法以系统 input-source ID 区分。显示名称只是便于阅读。
- 仅在启动、恢复、应用进入时判断规则。系统输入源变化通知用于更新显示，不触发强制改回，也不自动记忆新偏好。
- 只选择系统已启用、可选择的键盘输入源；当前已是目标时不重复调用。
- 不提供隐含默认输入法，不请求辅助功能或输入监控权限，不监听按键、不联网。
- 配置位于当前用户的 Library/Application Support/InputPilot/settings.json，只保存规则和暂停状态；登录项状态来自系统，不在此另存。
- 首次文件不存在是正常的空状态。JSON 损坏或缺少必需字段时停止应用规则、禁止保存，并显示错误，不把损坏文件覆盖成空规则。原子写入失败会保留界面中上一次成功保存的配置。
- 手动编辑 JSON 前请先退出 InputPilot；运行时不会监视外部对配置文件的修改。文件损坏时先保留副本，再修复内容；设置窗口提供“打开配置文件夹”和“重新读取配置”。

主要处理路径：

    NSWorkspace 应用激活通知
      → AppModel 当场读取前台应用与当前输入源
      → RuleEngine 检查暂停、规则、目标可用性
      → 需要切换才调用 InputSourceService → TISSelectInputSource

    系统输入源变化通知 → 读取实际输入源 → 更新显示（不强制切换）
    设置界面更改规则 → 校验 → 原子保存成功 → 更新界面状态

窗口参考用户提供的截图组织表格与操作区，使用系统字体、控件和外观重新实现，没有复制原软件代码或界面资源。采用 Swift Package 加打包脚本，便于用一条命令编译；不引入 Electron、WebView、第三方 UI 框架或守护进程。尚未做性能基准测试，不宣称内存或耗电一定低于原软件。
